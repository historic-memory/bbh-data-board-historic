# WO-03: Uji jalur 403 anti-escalation (H-8)

## Referensi
- SPEC: A-4, AC-5, GAP-5.
- `plugins/auth/services` (`EnsureCanGrant`, `ErrLastWildcardAdmin`=409, anti-escalation=403).
- `middleware.RequirePermission` → 403.
- CLI: `console auth create-admin`, `auth group assign|unassign`, `auth admin groups`.

## Persiapan
1. Buat **admin uji non-root** (mis. `qa-admin@local`), password kuat, **tanpa** grup `*`.
   Masukkan ke grup `admin` (baca+tulis) atau `viewer` (baca) sesuai skenario.
2. Login admin uji → simpan token.
3. **Catat**: root tetap utuh (jangan lepas `*` dari root terakhir; anti-lockout akan menolak
   `409`, tapi jangan sampai mencoba).

## Skenario (semua harus `403`)
| # | Skenario | Endpoint | Aktor |
|---|---|---|---|
| S1 | Memberi grup **root** (`*`) ke admin lain (escalation) | `PUT /api/admins/:id/groups` | admin uji (non-`*`) |
| S2 | Mengubah **keanggotaan grup sendiri** | `PUT /api/admins/:selfId/groups` | admin uji (non-`*`) |
| S3 | Memanggil endpoint yang butuh `resident.write` tanpa hak (grup `viewer`) | `POST /api/admin/residents` | admin uji viewer |

## Opsi otomatisasi
- Bila praktis, tambah test Go di `plugins/auth` yang membangun service dengan aktor non-`*`
  dan memverifikasi `Err` anti-escalation. Jika tidak, minimal **bukti manual** (curl) tercatat.

## Bukti yang dilampirkan
- Perintah + respons `curl` untuk S1, S2, S3 (harus `403` dengan pesan yang sesuai).
- Kontrol positif: admin uji pada grup `admin` berhasil `POST /api/admin/residents` (`201`)
  — membuktikan 403 bukan karena token salah.

## Kriteria Selesai
- AC-5: tiga skenario `403` terbukti dengan output nyata; kontrol positif lulus.
- Temuan (bila ada bug anti-escalation) dilaporkan; perbaikan kode hanya bila diperlukan
  dan dibatasi pada plugin `auth`.
